## Запуск

Потрібен Node.js 18+.

```bash
npm install
cp .env.example .env      # за замовчуванням увімкнено демо-режим
npm run dev               # http://localhost:5173
```

Інші команди: `npm test` (37 тестів), `npm run build` (збірка в `dist/`), `npm run preview` (перегляд збірки).

Наскрізний прогін у Chrome: `npm run build && npm run preview`, потім `pip install playwright && python e2e/run.py "<шлях до Chrome>"`. Скриншоти з’являться в `e2e/screenshots`.

Кнопка «Скинути демо-дані» в меню повертає згоди, запити й журнал до початкового стану.

## Безпека

Зміни за рецензією коду тижня 1 (EZW-48).

**Демо-пароль не потрапляє в робочу збірку.** Увесь демо-код (`src/api/mock.ts`, `src/api/mock/*`, разом із `DEMO_PASSWORD` і `DEMO_USERS`) підключається лише динамічним `import()` за умови `USE_MOCK`. Коли `VITE_USE_MOCK=false`, Vite вирізає ці гілки, і демо-модулі в `dist/` не потрапляють. Перевірка:

```bash
VITE_USE_MOCK=false npm run build
grep -c easyway2026 dist/assets/*.js   # має бути 0 у кожному файлі
```

У демо-збірці пароль лежить в окремому чанку `mock-*.js`, і цей чанк завантажується лише в демо-режимі.

**Токен не зберігається в localStorage.** Сесію (токен, профіль, час завершення) записано в `sessionStorage`. Вона діє до закриття вкладки й не довше за `expires_in` із відповіді /auth/login (у демо — 30 хвилин), після чого клієнт сам виходить із системи. Під час виходу або після завершення терміну сесію видалено. Старий запис у `localStorage` (з версії тижня 1) очищується автоматично. «Запам’ятати мене» тепер зберігає лише email (`easyway.lastEmail`), без токена.

**CSP у збірці.** У `dist/index.html` додається `Content-Security-Policy`: скрипти лише з власного джерела, без `unsafe-inline` і `unsafe-eval`; `connect-src` — лише джерело API; `object-src 'none'`. Тому JSON Schema-валідатори компілюються заздалегідь (`npm run gen:validators`, Ajv standalone), а не через `new Function` у браузері.

**Залишковий ризик і цільове рішення.** `sessionStorage` теж читається JavaScript-кодом, тож XSS-атака на сторінці могла б украсти токен. Ризик зменшують CSP, екранування React і короткий строк сесії, але не прибирають. Цільове рішення — токен в `httpOnly`-cookie з `Secure; SameSite=Strict`, яку встановлює бекенд (П4), плюс CSRF-захист. Клієнт до цього готовий: усі запити йдуть через `src/api/http.ts`, і там достатньо ввімкнути `credentials: 'include'` та прибрати заголовок `Authorization`.
